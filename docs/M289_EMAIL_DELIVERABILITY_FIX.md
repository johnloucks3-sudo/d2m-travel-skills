**Root cause of the bounce:** `concierge@` sends *through* Gmail (send-as alias). With no d2mluxury.quest DKIM and a malformed SPF, the message cannot achieve **DMARC alignment** on the From: domain → strict providers (iCloud, me.com) reject. Gmail-to-Gmail tolerated it; iCloud did not.

---

## The Fix — 3 DNS changes in Cloudflare (apply in order)

### 1. Repair SPF (replace the malformed record)
In Cloudflare DNS → the existing apex `TXT` SPF record, **delete and re-create** with a clean single line (no line breaks, no stray characters):

```
Type: TXT
Name: @            (d2mluxury.quest)
Content: v=spf1 include:_spf.google.com include:_spf.mx.cloudflare.net ~all
```
> The fix is removing the embedded control char. Keep `~all` (softfail) for now; tighten to `-all` only after DMARC has run in monitoring mode for 2+ weeks with no surprises.

### 2. Add DMARC (start in monitor mode — safe, breaks nothing)
Create a new TXT record:

```
Type: TXT
Name: _dmarc       (_dmarc.d2mluxury.quest)
Content: v=DMARC1; p=none; rua=mailto:dmarc@d2mluxury.quest; ruf=mailto:dmarc@d2mluxury.quest; fo=1; adkim=s; aspf=s
```
> `p=none` = monitor only (no mail is rejected — collects reports so we see alignment before enforcing). After 2–3 weeks of clean reports, raise to `p=quarantine`, then `p=reject`.
> If `dmarc@d2mluxury.quest` isn't a real mailbox, point `rua`/`ruf` at `johnloucks3@gmail.com` instead, or set up Cloudflare Email Routing to forward it.

### 3. Add DKIM (the piece that fixes the alignment failure)
DKIM must be generated by the system that *sends* the mail. Because `concierge@` sends via Gmail send-as, the domain needs to be a **Google Workspace** domain to publish Google DKIM:

**Path A — domain is in Google Workspace (preferred):**
1. Google Admin console → Apps → Google Workspace → Gmail → **Authenticate email**.
2. Select `d2mluxury.quest` → **Generate new record** (2048-bit).
3. Google gives a host (`google._domainkey`) and a long TXT value.
4. In Cloudflare DNS add:
   ```
   Type: TXT
   Name: google._domainkey
   Content: <the long v=DKIM1; k=rsa; p=... value from Google>
   ```
5. Back in Google Admin → **Start authentication**.

**Path B — domain NOT in Workspace (send-as from consumer Gmail):**
Consumer Gmail send-as **cannot** DKIM-sign as the custom domain — Gmail signs as `gmail.com`, so d2mluxury.quest DKIM will never align. Options:
- (b1) Add d2mluxury.quest to Google Workspace (≈$7/user/mo) → then Path A. *Financial commitment — Commander gate.*
- (b2) Keep the current workaround permanently: send client mail **as johnloucks3@gmail.com** (delivers fine, Gmail-aligned). Lose the branded From:.
- (b3) Route outbound through a service that signs for the domain (e.g., Cloudflare Email Workers / a relay). More infra.
