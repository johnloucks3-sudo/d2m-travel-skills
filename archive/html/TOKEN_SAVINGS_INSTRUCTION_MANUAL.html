Commander Keywords (Now Live)

Type these keywords in your prompts to control routing. No code changes needed.

@ctx — Sandbox Data Processing

Effect: Forces all work to sandbox (ctx_execute_file or ctx_batch_execute). Zero LLM tokens.

Example:

@ctx Extract JSON from this 500MB log file

Cost: ~100 tokens (just to load router). No Claude tokens burned.

@zen — ZEN Counter-Voice

Effect: Spawns independent reasoning immediately. Routes to free-infer (GitHub DeepSeek-R1 or Cerebras) or Poe points.

Example:

@zen Counter my argument with a refutation

Cost: $0 (free models) or Poe points (194K remaining).

@free — All Free Models

Effect: Routes all work through free_model_router (Groq, Cerebras, GitHub, Ollama). No Claude tokens.

Example:

@free Summarize this research paper

Cost: $0. Providers: Groq (Llama 3.3-70B), Cerebras (gpt-oss-120b), GitHub (Mistral, R1), Ollama (local).

@oc — Hand Off to OpenCode

Effect: Checkpoints all state to hale_bus. Claude Code goes dormant (except WF-17 gates). OpenCode takes over.

Example:

@oc I'm at 65% usage, take over

Cost: Depends on OpenCode model (DeepSeek V4 or Groq via opencode.json).

@oc-takeover — OpenCode Primary

Effect: Same as @oc but signals longer-term OpenCode operation. Claude Code is fallback only.

Example:

@oc-takeover Extended session, handle everything

@cc or @back — Hand Back to Claude Code

Effect: If OpenCode is running, releases missions and hands back to Claude Code with full state handoff.

Example:

@cc I'm done, give it back to Claude Code

Cost: Zero transition cost. Shared state via hale_bus, no missing context.

How It Works: State Handoff (CC ↔ OC)

Claude Code Session

  1. SessionStart hook loads keyword router
  2. session_init.py reads prior context from hale_bus (prior missions, alerts, cached ZEN)
  3. Main loop uses ClaudeCodePromptHandler to classify prompts
  4. Routes to: ctx_execute → free_infer → ZEN → Haiku (default)
  5. On shutdown: Stop hook checkpoints all state to hale_bus

OpenCode Session (after @oc)

  1. SessionStart reads hale_bus checkpoint from CC
  2. Claims all prior missions, loads alerts, FPD deadlines, cached ZEN
  3. Uses same keyword router config, routes to free models (Groq, Cerebras, GitHub, Ollama)
  4. Caches ZEN responses for CC to reuse
  5. On @cc/@back: releases missions, checkpoints, hands back

Seamless Handoff

  • Zero context loss — hale_bus carries: missions, FPD deadlines, alerts, ZEN cache
  • Mission status tracking — each instance knows what prior instance was doing
  • No manual sync needed — everything automatic via JSON checkpoint
