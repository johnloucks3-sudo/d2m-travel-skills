# Task 31: Migrating email_intel and intel_analysis to OpenCode

## 1. Client-Facing Assessment

**Part 1 — `core/email/thunderbird_email_intel.py` (Email Classification):**
**KEPT ON CLAUDE.** 
*Reasoning:* While the initial classification step (supplier vs. client) is routine analysis, the script itself actively generates client-facing emails directly via `_draft_client_response` and the `promo_prompt` drafts in the Commander's voice (John Loucks). Migrating the classification step to an async pipeline (`dispatch_to_oc`) would break the synchronous generation of these drafts. Because the script's primary downstream action is generating client-facing text, it falls squarely under the Commander's standing carve-out rule.

**Part 2 — `core/intel/thunderbird_intel_crew.py` (Intelligence Analysis Tasking):**
**MIGRATED TO OPENCODE.**
*Reasoning:* The `A2 Dembe` analysis stage produces an internal staff paper ("senior officer's daily read file"). The downstream output is an intel package strictly for internal review and consumption by the Commander via the morning brief. No text generated by this script is ever surfaced to a client. Thus, it is safe to migrate this analysis generation to OpenCode.
