### 1b. Retired/date-pinned model default — CONFIRMED ✅, WRONG LINE

### 1c. Unclosed stdin in `_spawn_background` — CONFIRMED ✅, WRONG LINE NUMBERS
- AG cited `lines 394-397` for the `_spawn_background` Popen. **Actual code at lines
  396-402**: `subprocess.Popen(cmd, stdout=open(log_file, "w"), stderr=subprocess.STDOUT,
  env=env, start_new_session=True)` — **no `stdin=` argument**.
- With no `stdin=`, Python inherits the parent's stdin (the terminal or calling process's
  pipe). Background subprocess blocks if it ever reads stdin — guaranteed hang path.
- **Fix: add `stdin=subprocess.DEVNULL`** to `_spawn_background` Popen call at line 396.
- **STATUS: CONFIRMED. AG named it correctly; line numbers are off by 2 (396 not 394).**

### 1d. Missing --mcp-config → MCP server startup hang — CONFIRMED ✅, ALREADY MITIGATED

## 2. CORRECTIONS / ADDITIONS AG MISSED OR GOT WRONG

### C1. `_spawn_background` stdin omission — AG named it but wrong line

### C2. `_spawn_background` has a **file handle leak** — AG missed this entirely
- Line 398: `stdout=open(log_file, "w")` — this `open()` call is never assigned to a
  variable and never explicitly closed. If `Popen` raises after the file is opened,
  the handle leaks. Low severity in practice (GC will close it), but it's a defect.
- **Fix**: `log_fh = open(log_file, "w"); proc = subprocess.Popen(..., stdout=log_fh, ...)`
  — or use a `with` block around the Popen + handle close after detach.
- **Confidence:** HIGH | **Severity:** LOW

  `"gemini-3.1-pro-high"`, `"claude-sonnet-4-6"` — all verified against live `agy models`
