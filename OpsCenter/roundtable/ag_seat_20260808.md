# POINT PAPER — EMAIL C2 / TASKING REDESIGN (AG SEAT)

**PURPOSE**
To provide the Gemini/Hale-AG independent assessment and design proposal for the Thunderbird Email C2 system redesign.

**BACKGROUND**
Current email C2 architecture is fragmented. The Commander requires a human-Exec model: every email yields a closed-loop response AND a tracked task, detailing WHO, RDD, ACTION, and DELIVERABLE.

**FINDINGS**
- Duplicate ingest paths exist. `email_task_ingest.py` is orphaned but still running, masking the true source of truth.
- Current classifier logic drops ACKs and CCs from task generation, treating them as noise rather than intent.
- Execution verification suppresses receipts, violating the closed-loop requirement.

**DESIGN**
- **Q1. Canonical Flow:**
  - **Survivors:** `run_commander_directive_sweep.py` (Ingest/Watcher), `core/comms/email_mode_classifier.py` (Classifier), `mission_board.json` (Task Store), `dispatch_and_email.py` (Reply Channel).
  - **Retired:** `email_task_ingest.py`, `thunderbird_tasking_watcher`, `email_c2.py`.
- **Q2. Disposition Matrix (Task + Response Guarantee):**
  - **TASKING:** Spawn active task. Reply: "Wilco. Executing."
  - **CC:** Spawn active task for assigned seat to analyze/act. Reply: "Roger. CC received, reviewing for action."
  - **ACK:** Spawn auto-closed record task. Reply: "Roger. Acknowledged."
  - **FYI:** Spawn auto-closed reference task. Reply: "Roger. Filed."
- **Q3. Human-Exec Feedback Loop:**
  - Every ingest triggers an immediate threaded reply using a strict receipt format injected by the classifier:
    - **WHO:** [Assigned Seat/Persona]
    - **ACTION:** [One-line summary]
    - **DELIVERABLE:** [Expected output]
    - **RDD:** [Date/Time]
- **Q4. Execution Fit (AG vs CC vs OC):**
  - **OC (DeepSeek/Local):** Default lane. Routine local execution, fast scripts.
  - **AG (Gemini Native/contact_ag):** Fast reasoning, massive context analysis, Google Workspace ops.
  - **CC (Claude Sonnet via contact_ag /ask-claude):** High-judgment architecture, complex debugging, deep reasoning.
- **Q5. Verification and Closure:**
  - **Active Tasks:** Closed via `core.silver.gate` cross-engine integrity check. Final closure triggers a completion email with findings/deliverables.
  - **ACKs/FYIs:** Auto-closed at creation without theater. The initial receipt is the only communication.

**OPINION**
The current gap is treating the email simply as a trigger for a headless script, rather than a conversation with the Chief of Staff. The receipt email is the most critical missing artifact — it proves the loop is closed and expectations are set before work even begins.

**RECOMMENDATION**
- Decommission `email_task_ingest.py` immediately.
- Refactor `run_commander_directive_sweep.py` to unconditionally write to `mission_board.json` and unconditionally trigger `dispatch_and_email.py` for the receipt.
- Enforce the WHO/RDD/ACTION/DELIVERABLE receipt block in `core/comms/email_mode_classifier.py`.
