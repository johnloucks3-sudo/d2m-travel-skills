1. GOAL DESCRIPTION


Establish a formal 10-Stage End-to-End Capability Lifecycle Framework (an expanded USAF OODA Loop) that takes a raw Commander thought, sculpts it into strategy, identifies the gap, searches for the exact tool, formats a proposal, presents a decision surface, obtains Commander approval, builds, validates, and commits to persistent memory.


---


2. THE 10-STAGE OPERATIONAL LOOP



graph TD
    S1[1. Thought Ingestion] --> S2[2. Strategic Sculpting]
    S2 --> S3[3. Whetstone Gap Analysis]
    S3 --> S4[4. Search Prompting & Recon]

    S7 -->|Approved| S8[8. Design & Plan Drafting]

    S9 --> S10[10. Terminal Report & Memory Commit]

Breakdown of Stages:


1. Stage 1: Thought Ingestion (Observe I)

Captures raw Commander thoughts verbatim from chat, voice logs, or emails. Assigns tracking ID `CAP-YYYYMMDD-XX`.

2. Stage 2: Strategic Sculpting (Orient I)

Refines raw thought into a clear, strategic outcome statement ("What does victory look like?").

3. Stage 3: Whetstone Gap Analysis (Orient II)

Cross-checks existing codebase, tools, and subagents to isolate the exact technical gap.

4. Stage 4: Recon & Search Prompting (Orient III)

Formulates targeted multi-vector search queries (Anansi / PyPI / GitHub / arXiv) to locate candidate tools.

5. Stage 5: Capability Recognition (Orient IV)

Evaluates candidates against Thunderbird rules ($0.00 off-meter cost, Python/systemd fit, safety).

6. Stage 6: Proposal & Portal Delivery (Decide I)

Formats USAF Point Paper with HALE-AG 4-Star Lead comments. Renders to Executive HTML Portal + 3-tier notification.

7. Stage 7: Commander Decision Surface & Gate (Decide II)

Presents explicit decision buttons/text. Waits for explicit Commander text approval in chat (`Approve` / `Wilco`).

8. Stage 8: Architectural Design & Plan Drafting (Act I)

Drafts durable `.md` and `walkthrough.md` with ASCII progress bars.

9. Stage 9: Delegated Build & 3-Point Test Validation (Act II)

Delegates mechanical build to JET (OpenCode @ $0.00). Runs 3-point systemd audit linter & live tests.

10. Stage 10: Terminal Reporting & Memory Commit (Act III)

Reports in terminal past tense ("Done. Did X, Y, Z."). Writes persistent memory to `~/.claude/projects/.../memory/` and updates `MEMORY.md`.
