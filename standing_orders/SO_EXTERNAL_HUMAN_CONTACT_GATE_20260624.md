# SO — EXTERNAL HUMAN CONTACT GATE
*Standing Order 2026-06-24 | Commander directive, grant/build session*
*Author: V. Hale, VCS | Status: ACTIVE*

---

## THE RULE

Any Wing-initiated or Wing-responsive message to a real person outside the Wing follows this protocol — **without exception**:

1. **Draft** the message (full text, formatted, signature block included)
2. **Telegram alert** to Commander with the draft text
3. **Three options** presented: **Send / Revise / Delete**
4. Commander selects one. Wing executes.

---

## SCOPE

This gate applies to:
- **Clients** — unchanged from existing WF-17
- **Vendors and suppliers** — cruise lines, tour operators, hotel partners, airline group desks
- **External data/service providers** — Project Expedition, GetYourGuide, Viator, TAAP, Silversea excursions, any external TA portal contact
- **Any real person outside the Wing** — including booking agents, group desk reps, insurance providers, restaurant contacts on behalf of clients
- **Inbound correspondence** — if an external party contacts the Wing and a response is warranted, draft + gate before any reply exits

---

## WHAT IS NOT GATED

- Internal Wing communications (johnloucks3, persona-to-persona)
- Automated API calls / web scraping (data retrieval, not human correspondence)
- Internal reports, briefs, state files (these go direct to johnloucks3 inbox per existing routing)

---

## TRIGGER INCIDENT

2026-06-24: Commander identified Wing contact with Project Expedition without his knowledge. Investigation ongoing to identify the specific message. This SO prevents recurrence.

---

## ENFORCEMENT

- Hale is responsible for gating all outbound human contact
- Any persona, headless dispatch, or agent that routes human correspondence must surface it to Hale first — Hale gates it
- Violations logged in `hale_decisions.md` under GATE VIOLATION header
- First violation = log + correct. Second = Commander brief.
