## PROVISION 1 — SEND GUARD (FAIL-CLOSED, NON-NEGOTIABLE)

The auto-reply function fires **only** when the sender address is exactly `johnloucks3@gmail.com`. This is the Commander's within-wing address, explicitly authorized for full-send by SO 2026-03-24.

**For every other sender — including all client addresses, vendor addresses, and unknown senders — the agent MUST NOT send autonomously.** Default action is WF-17 draft path: draft the reply, stage in johnloucks3 Gmail drafts labeled `THUNDERBIRD-Commander-Review`, notify Commander via Telegram, stop.

Fail-closed means: if the sender check is inconclusive, ambiguous, or fails for any technical reason, the system defaults to draft — never to auto-send. There is no "probably-OK" path to auto-send.

This provision reconciles with SO 2026-06-08 (protected email/relay files): `core/email/email_conversation_agent.py` is within the agent's own architecture and is NOT on the protected-file list. Any modification to `OpsCenter/relay_send.py`, `core/relay/wing_relay.py`, or `OpsCenter/dispatch_and_email.py` remains governed by SO 2026-06-08 and requires CC authorization.

## PROVISION 2 — AI IDENTITY DISCLOSURE

Every AI-generated reply in the email conversation loop MUST carry an identification line in the signature block. Canonical form:

> *This reply was generated by the Thunderbird Wing AI (Hale, powered by Claude). For human review, email johnloucks3@gmail.com.*

This line is non-negotiable, non-suppressible, and applies regardless of how natural the reply reads. Applies to both the wing-internal path and any AI-assisted draft destined for client review.

---

## PROVISION 3 — THREAD STATE

Thread state is maintained in `OpsCenter/email_conversation_state.json`, keyed by Gmail thread ID. Schema:

```json
{
  "<thread_id>": {
    "last_updated": "<ISO-8601>",
    "sender": "<email>",
    "subject": "<subject>",
    "turn_count": 0,
    "path": "wing_internal | wf17_draft | classified_other",
    "messages": [
      {"role": "user|assistant", "content": "<text>", "ts": "<ISO-8601>"}
    ]
  }
}
```

Thread state is loaded before every reply call and updated after. A thread without state is treated as a new conversation — never inferred.

## PROVISION 6 — MONITORING & HEALTH

The `email_conversation_agent.py` daemon is a CI-adjacent service. It runs under systemd with a 2-minute poll interval.

Health probe: daemon running AND last successful poll < 5 minutes ago.

If the daemon misses 2 consecutive polls: page Hale via Telegram. If 5 consecutive: P0 alert, escalate to Commander.
