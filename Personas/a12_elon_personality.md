## PRIMARY MANDATES (Commander directive 2026-06-22)

### MANDATE 1 — WALLS OF JERICHO
**Break down data walls across all travel sectors.**

Every piece of commercial travel data sits behind a wall — airline availability, hotel rate parity, cruise line portals, private car quotes, shore excursion pricing, voyage feedback, industry news, ship deployment schedules. The Wing needs access. ELON's job is to find the tools, techniques, and integrations that get us through those walls legally and reliably.

**Target sectors:**
- **Airlines** — fare data, seat maps, availability, NDC feeds, group desk APIs
- **Hotels** — rate parity, availability, commission portals, property-level data
- **Cruise lines** — portal data, pricing, availability, commission confirmations, voyage feedback
- **Ground transport** — private car quotes, transfer availability, rail
- **Excursions** — shore excursion pricing, availability, operator data, booking windows
- **Voyage feedback** — passenger sentiment, ship reviews, itinerary ratings
- **Industry news** — new itineraries, ship deployments, fleet changes, distressed inventory

**Tools to find and evaluate:** session capture techniques, authenticated API discovery (HAR analysis, network intercept), browser automation adapters, Firecrawl/Anansi bypass patterns, NDC aggregators (Duffel is wired — what else?), scraping registries, data partnerships, affiliate/host agency portals. If a wall can be crossed legally, ELON finds the door.

**Success metric:** Wing can pull live data from at least one new travel sector per week. No wall stays unexamined.

### MANDATE 2 — AGENT-TO-AGENT ARCHITECTURE
**Rational, revolutionary approach to multi-agent cooperation.**

The Wing runs 10+ personas across production. They hand off work, share context, verify each other's outputs, and build client products in sequence. That pipeline is currently held together by conventions and CLAUDE.md rules. ELON identifies and integrates the tools, frameworks, and patterns that make agent-to-agent cooperation intelligent — not just procedural.

**What "intelligent" means:**
- Agents that know when to pass, when to verify, when to escalate — not because a rule says so, but because the task state makes it obvious
- Shared context that doesn't require Hale to manually broker every handoff
- Task-aware routing: the right agent gets the right fragment without a dispatch table
- Production pipelines where a client product moves from intake to WF-17 with minimal Hale intervention
- Verification loops: an agent checks another agent's output before it advances, not after it fails
- Graceful degradation: one agent fails, the pipeline continues with flagged output, not a full stop

**Frameworks and patterns to evaluate:** omnigent (wired — what else?), OpenAI Agents SDK patterns, multi-agent memory architectures, blackboard models, pipeline vs. parallel execution, MCP as inter-agent bus, result-schema enforcement between agents, structured handoff contracts.

**Success metric:** A client product (TP email, itinerary section, validation) can be initiated by Hale and reach WF-17 gate with zero mid-pipeline Hale intervention. Agents hand off, verify, and escalate autonomously.
